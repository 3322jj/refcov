How much of your reference material did the AI actually read?

Without RefCov, 13 of 16 runs wrote their code without opening any of the registered guides. With RefCov, all 16 runs read every required unit before they wrote.

Scope: five front-end tasks, claude-haiku-5.5 on kiro-cli 3.3.0 (the version of the first task is inferred), three or four runs per group per task. These are descriptions of 16 runs, not statistics. Sources: front-end trial, section 5 (first task) and front-end extension trial, section 7 (all five tasks).

        What this does not show

        • Reading is not following. A guide that the model read did not always lead to its practices. After reading, several runs chose conservative browser-support code.
        • The GIS app does not show that reading changes the answer. Three GIS rounds, including a published benchmark task, did not measure that.
        • RefCov adds information the model lacks or does not use: project standards, newer practices it knows but skips, and team conventions. It does not add skill for long workflows or hard libraries.
        • It helps most where the material is large or costly to read in full, and where the material is a means rather than the task. For a short document that the prompt names, the model often reads it anyway, and RefCov only adds a record.
        • The numbers are small: three or four runs per group, one task at a time. They describe those runs and are not statistics.
        • Test conditions: the front-end and GIS results are claude-haiku-5.5 on kiro-cli 3.3.0. The first front-end task also had automatic model selection and claude-sonnet-5.5 groups. The video trial used claude-sonnet-5.5 on two batches, kiro-cli 3.1.0 and 3.3.0.
        • A person registers the materials. RefCov does not look up the latest guides by itself.
        • RefCov records that a unit was read, not that it was understood.
        • RefCov records that a unit was read in this workspace, not which agent read it. While this page was being built, Kiro had sub-agents read 174 guide units for it, and the gate let the next write through. Kiro reported this itself.

        Try it yourself

        These are the Setup steps in short. If this page and the README differ, the README is right.

        1. Install RefCov with uv: uv tool install git+https://github.com/3322jj/refcov.
        2. In your project root (the folder that holds .git), run refcov init, then refcov doctor.
        3. Open the project in Kiro and trust the workspace. Until you trust it, Kiro does not load the project's MCP configuration; in our test the hooks also showed as disabled.
        4. List your reference files under [sources] in refcov.toml, then run refcov sync.

        The full steps are in the Setup section of the README.
