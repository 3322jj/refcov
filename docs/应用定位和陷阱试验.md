# 两个应用的定位、演示画面和陷阱试验

2026-11-12，Claude 写，用户定方向。这份文档定方向，不是规格；规格由 Kiro 按它另写。

## 1. 结论

- 两个应用不是两个查看器，是两个"陷阱"：各有一些单元，AI 不看就会做出错的结果。
- **图层覆盖率（GIS）做主线，做透**。它负责证明"不看会出错"，对照实验只做它。
- **镜头覆盖率（视频）做轻，放开场**。它负责让人几秒内看懂"覆盖率"是什么。
- 主陷阱不用坐标系。用"数据文件里看不出来、只有读了说明才知道"的那一类。
- 动手做应用之前，先做第 5 节的试验。试验不通过，主线要重想。

## 2. 两个应用各自的角色

| | 图层覆盖率 `apps/layer-coverage` | 镜头覆盖率 `apps/shot-coverage` |
|---|---|---|
| 角色 | 证据 | 画面 |
| 深度 | 做透 | 能跑、明显不同、有独立入口 |
| 单元 | 图层的坐标系、范围、每个字段（文件里看到的 + 数据字典里写的） | 一个镜头：关键帧、时长、台词 |
| 不看会怎样 | 数字错，而且看起来正常 | 漏掉后面的镜头 |
| 对错 | 有标准答案，能数 | 主观 |
| 对应评分 | 真实用途、创新 | 设计、展示 |

规则只要求两个明显不同的应用、各占一个文件夹，没有要求一样深。但两个都必须真的能跑，和视频里展示的一致。

## 3. 主陷阱怎么选

坐标系不合适，原因有两个：太常见；而且坐标系存在数据文件里，AI 用常见的库一打开就看得到，多半会主动查，陷阱不触发。

好陷阱的条件：

1. 数据文件本身看不出来，只有随附的说明文档里写了。
2. 错的结果看起来正常。结果离谱的话 AI 自己会起疑去查，对照实验拉不开差距。
3. 不懂 GIS 的程序员也能一句话听懂。
4. 有标准答案，能判对错。

## 4. 数据集：纽约市建筑轮廓（NYC Building Footprints）

选它的理由：官方数据字典本身就是一个 Markdown 文件，现有的文档适配器直接能登记；几个陷阱都是数据本来就有的，不是编的。

### 已核实（2026-11-12，读了官方元数据原文）

- 数据字典：<https://github.com/CityOfNewYork/nyc-geo-metadata/blob/main/Metadata/Metadata_BuildingFootprints.md>
  - 原始文件约 13 KB，按 `text/plain` 提供，路径以 `.md` 结尾，符合 `refcov add <网址>` 现在接受的条件。
  - 所在仓库的许可证是 Apache-2.0。
- 字典里写明的、数据文件里看不出来的事：
  - `FEAT_CODE`（要素类型）：不是每条记录都是建筑。2100 是建筑，5100 在建，5110 车库，1001 加油站顶棚，1002 储罐，1004 附属构筑物，1005 临时构筑物，**1003 是占位三角形**（没有影像和图纸时画的小三角）。
  - `CNSTRCT_YR`（建成年份）：**0 或空表示不详**。
  - `HEIGHTROOF`（屋顶高度）：单位是**英尺**，是高出地面的高度，不是海拔；**0 或空表示不详**。
  - `BIN`（建筑编号）：**不唯一**。编号不详时用 1000000、2000000 这类占位值；一栋楼被地块线切开时多个图形共用一个编号。要唯一标识用 `DOITT_ID`。
  - `LSTSTATTYPE`（最后状态）：取值里有 Demolition 和 Marked For Demolition。
  - 坐标系：原生是 EPSG:2263（单位英尺）；不同下载渠道给的是 3857 或 4326。
- 使用限制：元数据写"Open Data policies and restrictions apply"，访问权限是 Public。NYC Open Data 的使用条款说数据供参考、不作任何保证。

### 没核实

- **0 和空在实际下载的文件里各占多少。** 字典写的是"0 或空"。如果全是空，常见的库算平均值时会自动跳过，这个陷阱就不成立。要拿真实数据数一遍。
- **非建筑要素、状态为拆除的记录各有多少。** 太少的话对结果影响小，陷阱不明显。
- **能不能把裁出来的一小块数据放进公开仓库。** NYC.gov 的使用条款全文我没读。稳妥的做法是仓库里不放数据，只放下载脚本和数据字典的登记，注明来源。
- 全市数据约一百万条记录、几百 MB。演示只用一个街区的子集。

### 备选

纽约市地块数据 PLUTO 也核实了两条：建成年份为空或 0 表示不详；坐标是纽约长岛州平面坐标系。但它的数据字典是 PDF，现在没有适配器，所以排在后面。

## 5. 先做的试验：不装 RefCov，AI 会不会掉进去

目的：确认陷阱真的会触发。不触发的话，对照实验没有差别可讲。

### 第 0 步：数一遍数据

选一个街区，下载子集，数出：各 `FEAT_CODE` 的条数；`CNSTRCT_YR` 为 0、为空的条数；`HEIGHTROOF` 为 0、为空的条数；`LSTSTATTYPE` 各取值的条数；重复的 `BIN` 有多少。

哪个陷阱在这个街区占比高，就用哪个。都很低就换街区。

### 第 1 步：定一个问题

问题要同时踩到两三个陷阱，而且有唯一答案。例如：

> 这个街区 1940 年以前建成的建筑有多少栋？它们的平均屋顶高度是多少米？

这一个问题里有三处会错，每一处错了结果都还像样：

1. 建成年份为 0 的记录满足"小于 1940"，会被算成老建筑。
2. 储罐、顶棚、占位三角形被算成建筑。
3. 高度当成米；高度为 0 的记录拉低平均值。

标准答案用脚本按数据字典的说法算出来，先写好。

### 第 2 步：跑

- 工作区里放数据和数据字典，提示词里说明"数据说明在某某文件"，和真实用户给材料的方式一样。不装 RefCov 的钩子和 MCP。
- 同一个问题跑 10 次，每次新开会话。
- 每次记三样：它有没有打开数据字典；它的答案；三处陷阱各对没对。

### 判定

- 10 次里至少 4 次有至少一处错：陷阱成立，照这个做主线。
- 只有 1 到 3 次错：换问法或换陷阱再试一轮。
- 一次都不错：GIS 这条主线立不住，回来重想。

门槛是我定的，没有依据，可以调。

这个试验交给 Kiro 或便宜的模型跑，不用 Claude。

## 6. 视频里该出现的画面（3 分钟以内）

1. **开场，约 20 秒**：AI 说"参考材料我都看过了"，旁边是记录：12 个镜头只取了 3 个。
2. **镜头覆盖率，约 30 秒**：镜头条 3 格亮、9 格灰。AI 写文件被拦，原因里列出没看的镜头。读完，整条亮起，放行。
3. **图层覆盖率，约 60 秒**（主线）：
   - 不装 RefCov：AI 直接写脚本，给出一个像样的数字。旁边是标准答案，差了多少。
   - 装了 RefCov：写文件被拦，原因点名"建成年份"这个字段单元。AI 读了，需求里标上出处，结果和标准答案一致。
   - 一条没标出处的需求被列为幻影需求。
4. **对照数字，约 30 秒**：同一个问题，装和不装各跑若干次，各对了几次。
5. **骨架，约 30 秒**：适配器接口有几个函数，两个适配器各多少行；规格、钩子、MCP、引导文档各一个镜头。
6. **收尾，约 10 秒**。

不许出现第三方商标和受版权保护的内容。

## 7. 镜头覆盖率做到哪一步

- 一个适配器：把一段视频按镜头切成单元，每个单元有关键帧、起止时间、台词。
- 一段演示视频：用户自己拍的。
- 一个页面：镜头条，看过的亮、没看的灰。
- 一次真实会话的记录，演示页能回放。

不做：理解镜头内容的模型、剪辑功能。

## 8. 风险，按先后排

1. **第 5 节的试验结果。** 最先做，决定主线成不成立。
2. **MCP 返回的图片，Kiro 的模型看不看得到。** `docs/验证结果.md` 测过 MCP 图片，结论要对一下。看不到的话，镜头单元只能退成文字。
3. **数据能不能放进公开仓库。** 见第 4 节。
4. **字段单元怎么来。** 数据字典里所有字段在同一个表格里，文档适配器会把整张表切成一个单元。图层适配器要自己把每个字段做成一个单元，把"文件里看到的"和"字典里写的"合在一起。这是图层应用规格里要定的第一件事。
