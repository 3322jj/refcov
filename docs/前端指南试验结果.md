# 前端指南试验：测出了漏读，也测出了 RefCov 的作用

EN summary: After more than fifteen controlled runs in which every agent read diligently, a front-end task finally reproduced skipped reference material. The workspace holds Chrome's modern web guidance (210 guides, Apache-2.0) and a one-line README saying front-end code follows them. With Kiro's default model selection (auto), 4 of 4 runs opened no guide and applied none of the four guide practices; a fixed claude-sonnet-5.5 read 6–7 relevant guides every time. With RefCov installed (8 relevant guides registered, 82 required units, strict mode), the same auto setting read all 82 units in 4 of 4 runs and applied all four practices every time, at about 7 times the credits of the bare auto runs and about the same credits as Sonnet. The write gate never had to block: the per-message status line was enough. Numbers are from 4 runs per group on one task.

2026-11-14 夜，Claude 直接跑的小样本探测（用户要求"最小测试"），没有经 `run_trial.py`，运行器和判分脚本在仓库外 `D:\agent\kiro\refcov-trial-grader\review-probe\`。

## 1. 为什么前面测不出来

前面十几次（GIS 陷阱、视频、网店约定、随口提问、120 份工单）全都认真，原因是：题都能靠搜索直接找到答案，或者不查就做不对；材料小到一条命令能全打印；大多用固定的 Sonnet。这一轮同时满足三个条件：

1. **AI 自以为熟悉的领域**：前端。
2. **不查也能交差**：老写法照样能跑，不会算错数字。
3. **默认设置**：Kiro 的自动选模型，大多数用户实际在用的。

## 2. 材料和任务

- 工作区：Chrome 官方现代前端指南（`modern-web-guidance` 包的 `guides/`，210 份，约 2 MB，Apache-2.0）加一句 README："Front-end code in this project follows the guides in guides/ (Chrome's modern web guidance)."
- 提示词（三组完全相同，不提 RefCov，不提读指南）：写一个账户设置页 `index.html`（纯 HTML/CSS/JS）：表单两个必填字段、"删除账户"按钮弹出确认框、点外面能关、弹框时背后不滚动、用户动过字段才显示错误。
- 四根"针"：任务里四个要求各对应一份指南推荐的新写法。

| 要求 | 指南推荐 | 老习惯 |
|---|---|---|
| 点外面关闭 | `closedby="any"`（`light-dismiss-a-dialog.md`） | JS 判断点击位置 |
| 动过才显示错误 | `:user-invalid`（`required-field-feedback.md`） | JS 加 touched 类 |
| 按钮打开对话框 | `command` / `commandfor`（`declarative-dialog-popover-control.md`） | JS 调 `showModal()` |
| 背后不滚动 | `overscroll-behavior` 等（`prevent-page-scroll-under-modal-dialog.md`） | JS 给 body 加 `overflow: hidden` |

- 判分：`index.html` 里有没有这四种写法；对应指南的原文有没有出现在工具输出里（读到没有）；最后的汇报怎么说。

## 3. 结果（kiro-cli 3.3.0，各 4 次）

| 组 | 打开指南 | 四种写法用上 | 用时（秒） | 额度 |
|---|---|---|---|---|
| 自动选模型，不装 RefCov | **4 次都是 0 份** | **0 / 16** | 22–32 | 0.32–0.46 |
| 固定 claude-sonnet-5.5，不装 | 每次 6–7 份相关指南 | 14 / 16 | 67–138 | 1.99–3.79 |
| 自动选模型，**装 RefCov** | **4 次都读完 82 个单元** | **16 / 16** | 91–104 | 2.36–3.52 |

- **不装 RefCov 的自动选模型**：4 次都只用 1–3 次工具调用，不列目录、不看 README，凭记忆写完；汇报诚实地说"没在浏览器里试过"，但对项目里的指南只字不提。
- **Sonnet** 两次没用 `commandfor`：读过指南后判断特性还不够普及，选了保守写法，算读了之后的取舍，不算漏读。
- **装了 RefCov 的自动选模型**：4 次都由发消息时的状态行提示（"参考材料要用 RefCov 的 MCP 工具读"）引导，先经 MCP 把 82 个单元全读完再写文件；**写文件关卡一次都没拦**。汇报里也写了"按指南做"。

运行文件夹：`D:\agent\kiro\refcov-trial\runs\web-20261114-214152`、`web-20261114-214552`（不装）、`webrefcov-20261114-215402`（装）。

## 4. 能说什么、不能说什么

可以说（只说在这一个任务、kiro-cli 3.3.0、各 4 次上测得）：

- Kiro 默认的自动选模型，在项目里明明有规范的情况下，4 次都没看规范就写完了。
- 装上 RefCov 后，同样的默认设置 4 次都读完了必看的指南，指南推荐的写法全部用上（16/16；Haiku 装上是 7/8，合起来说"基本全用上"）。
- 代价：额度约为不装时的 7 倍、用时约 4 倍；和固定 Sonnet 不装时差不多。

不能说 / 要照实交代：

- **这次起作用的是"读"（状态行和 MCP），不是"拦"**：关卡一次都没触发。"拦"的证据仍然只有 CLI 关卡验证那一次（qwen 先拦后读）。
- 登记的 8 份指南是 Claude 按任务挑的，四根针所在的指南都在里面。真实项目里团队也会登记和当前组件相关的规范，但这一点要在对外材料里写明。
- 自动选模型每次实际用的是哪个模型，日志里看不到。
- 每组只有 4 次，是描述，不是统计结论。

## 5. 补测：最便宜的模型装上 RefCov（2026-11-14 夜）

用户的问题："是不是更差的模型装上 RefCov，和强模型结果差不多，花得还更少？"自动选模型身份不明，所以换成明确便宜的固定模型 claude-haiku-5.5（倍率 0.06，Sonnet 是 1.3），各 2 次，其余完全相同。

| 组 | 打开指南 | 四种写法用上 | 用时（秒） | 额度 |
|---|---|---|---|---|
| Haiku 5.5，不装 | **2 次都是 0 份** | **0 / 8** | 38–41 | 0.04–0.05 |
| Haiku 5.5，**装 RefCov** | **2 次都读完 82 个单元** | **7 / 8** | 126–132 | **0.25–0.26** |
| Sonnet 5.5，不装（第 3 节） | 每次 6–7 份 | 14 / 16 | 67–138 | 1.99–3.79 |

- Haiku 装上 RefCov 后，写法用上的比例（7/8）和 Sonnet 不装时（14/16）相同，额度约为 Sonnet 中位数（约 2.7）的十分之一。
- 漏的那一条又是 `commandfor`，和 Sonnet 一样。
- 关卡同样一次都没拦，起作用的仍是状态行和 MCP。Haiku 读的时候有几个单元 ID 写错、返回空，它自己用 `check` 查出没读到的再补读，最后 82 个全部读到。
- 粗查：所有页面的脚本都能通过语法检查，都有 `<dialog>`、必填、邮箱类型和 aria 属性。Sonnet 的页面更长（11–15 KB，对 Haiku 的 9–10 KB），多写了降级方案。**页面在浏览器里是否真的好用，这次没有测**，"效果相当"只指四种指南写法。
- 只有各 2 次、一个任务，只能说"在这个任务上测得"。

## 6. 下一步建议

1. 这组对比作为"真实用途"的主要证据，演示页回放其中一对（不装 / 装）的会话记录。
2. 视频对比试验的结论保留为"拆"的证据（大材料读得全、更快更稳）。
3. 要补"拦"：可以把状态行关掉（只留关卡）再跑自动选模型一组，看它被拦后会不会去读。这是单独的一步，等用户定。
