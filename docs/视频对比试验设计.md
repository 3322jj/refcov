# 视频对比试验设计（草稿，等用户审阅，审完才跑）

EN summary: Draft design of the video comparison trial (sprint plan checkpoint 2). Task: with a 7:40 reference video, write a 30-second edit plan that begins with a table of borrowed techniques, each with a label from a fixed list and the time it occurs in the reference. Group A has only the video and the usual tools. Group B has the video, the shot adapter, MCP tools, hooks and the strict-mode gate. Same model (claude-sonnet-5.5), same prompt, 3 runs each, 30-minute cap, alternating, every run in its own folder with its own temp directory. Grading is automatic on the technique table: label, time, and whether that technique really happens at that time in the answer key outside the repository; descriptions are judged by hand. The decision rules are a draft, also written into the DEVLOG before anything runs. Nothing has been run for this trial; V-01 (a different task) was stopped and is not part of it.

状态：**草稿，2026-11-14。没有跑任何被测运行。** 依据 `docs/应用定位和陷阱试验.md` 第 4 节、`docs/冲刺计划.md` 第 3、10 节、`.kiro/specs/shot-coverage/design.md` 第 11 节。判定规则草稿同时写进了 `docs/DEVLOG.md`（2026-11-14）。**审阅通过后才改脚本、做模板、开跑。**

## 1. 要回答什么

材料大（7 分 40 秒、941 MB）、材料只是手段而不是任务本身时：装了镜头应用和关卡的 AI，（1）交不交得出东西，（2）交出来的东西里"借鉴手法的时间"对不对，（3）用时和额度怎样。**"更快、更省"只在测出来之后才讲；测出来对我们不利的也照报；只说"在某模型上测得"**（`product.md`）。

不回答：RefCov 能不能防蓄意伪造（不防）；别的模型会怎样；一般的视频。

## 2. 任务和提示词

两组用**同一个**提示词，不提 RefCov，不提用什么工具（英文，存为 `D:\agent\kiro\refcov-trial-grader\prompt-P.txt`）：

```text
reference.mp4 in this workspace is a reference video (about 7 minutes 40 seconds). Use it as your reference for pacing, transitions and on-screen text style, and write edit-plan.md for a new 30-second video about how a bicycle's gears work.

edit-plan.md must have two parts.

Part 1, "Borrowed techniques": a table with one row per technique you borrow from the reference video. Columns: label, time in the reference video, what it looks like. The label must be one of: hard-cut, soft-transition, white-flash, text-on-screen. The time is where the technique appears in the reference video, written as mm:ss.s (for example 01:23.4). List at least 6 and at most 12 techniques. List only techniques you actually found in the reference video, at the times you actually found them.

Part 2, "Shot list": the new 30-second video as a table with columns: time range, what is on screen, on-screen text, transition. Use the labels from part 1 for the transitions. Every transition you use must appear in part 1.

Write the file as edit-plan.md in the workspace root.
```

- 新主题（自行车变速）和参考视频的内容（AI 代理的事）无关，不会让模型靠常识猜。
- 标签只有四个，才能自动判分：`hard-cut`（硬切）、`soft-transition`（推近、淡入等软切换）、`white-flash`（白闪）、`text-on-screen`（画面上有字）。6–12 条，两组条数可比。
- 和定位文档第 4 节的示意相比：加了固定标签和条数范围，其余意思不变。

## 4. 运行规则

- 每次运行都经 `run_trial.py` 起新的 `kiro-cli chat --v3 --no-interactive --trust-all-tools --model claude-sonnet-5.5 --output-format stream-json` 进程，在各自的运行文件夹里，**不许自己答，不许用子 agent 代跑**。
- **单次上限 30 分钟**（V-01 的做法），到点结束整棵进程树，记超时。
- **3 次 A、3 次 B，交替**（A-01、B-01、A-02、B-02……），同一时段的网络和服务状态不会只影响一组。顺序执行，不并行。
- **临时目录设在运行文件夹里**：`run_trial.py` 起进程前建 `<运行文件夹>\tmp`，把 `TEMP`、`TMP`、`TMPDIR` 设成它（V-01 用了系统临时目录，三次共用、互相污染）。
- **碰到下面这些路径就作废这次运行**（用户 2026-11-14 细化）：原工程 `D:\agent\claude`、判分目录 `refcov-trial-grader`、别的运行文件夹、素材目录 `materials`。系统临时目录等不再作废，但应已被设到运行文件夹里。
- 基础设施故障（`kiro-cli` 崩溃、B 组 MCP 起不来、网络断）：这个位置作废、重跑一次、记进 DEVLOG；不是模型的表现，不计入结果。
- **需要对 `run_trial.py` 做的改动**（审阅通过后做，改动写进 DEVLOG）：起进程时设 `TEMP`、`TMP`、`TMPDIR`；`VB` 组按 `B` 组的办法写 MCP 配置、加 `--require-mcp-startup`；`--no-grade` 照用，另用新的判分脚本。
- 已知缺口：**超时的运行看不到额度用量**（V-01 的教训）。超时运行的额度记"未知"，不估算。

## 5. 记什么和怎么判分

新判分脚本 `grade_plan.py`（审阅通过后写，放在 `refcov-trial-grader`，旧的 `grade_video.py` 不动）。标准答案取自 `video_key.json`（仓库外，不放进运行文件夹）。

**交没交**：`edit-plan.md` 在运行文件夹根目录、两个部分都在（第一部分有表格）。

**第一部分的每一行**判一次，只看标签和时间（自动）：

| 标签 | 算对：时间落在 |
|---|---|
| `hard-cut` | 43 处硬切任一处的 ±1.0 秒内 |
| `soft-transition` | 22 处软切换任一处的 ±1.0 秒内 |
| `white-flash` | 两次白闪（119.3 秒、217.73 秒）任一次的 ±1.0 秒内 |
| `text-on-screen` | 161 条画面文字里任一条的出现时间段，两端各放宽 0.5 秒 |

行的状态：**对**（上表）、**错**（标签合法、时间不在上表范围内，即编出来的）、**无效**（标签不在四个里，或时间读不出）。时间接受 `mm:ss.s`、`m:ss`、`ss.s s` 几种写法。条数不在 6–12 的运行照判，另标。

- 每次运行的数：条数、对、错、无效、**准确率 = 对 / 条数**。
- **描述是否编造**：`what it looks like` 一栏由 Claude 逐条判（每次运行抽全部，条数不多），只判时间对的行；记"描述和那个时间的画面不符"的条数。这一项是手工的，不进自动规则。

**怎么看的视频、花了多少**（两组都记）：用时、额度（有则记，超时记"未知"）、工具调用次数、看图片的次数、是否自己跑了 ffmpeg 或写脚本、`edit-plan.md` 是由写文件工具还是 shell 建的（B 组的关卡只拦写文件工具，shell 写拦不住，如实记，不算作弊但要标出）。

**B 组另记**：用 `shot-coverage count` 数读过几个镜头（共 46 个）、读取次数、图片张数；日志里的 `block` 条数和顺序（先拦后读还是先读后拦）；有没有在没读完时就用 shell 写出 `edit-plan.md`。

**两组都记**：是否碰了作废的路径、临时目录是否在运行文件夹里、MCP 是否起来（B）。

## 6. 判定规则草稿

**同时写进了 `docs/DEVLOG.md`，审阅通过后改成定稿，跑完不改。** 次数只有 3 对 3，所有结论是描述性的：只说"在 claude-sonnet-5.5 上、这一个视频、各 3 次的结果"。

- **R1 交得出**：B 组 3 次里至少 2 次交出 `edit-plan.md`，才谈得上后面的比较；否则结论是"装了也没交出来"，原因照实写。
- **R2 比 A 组交得出更多**：B 组交出的次数大于 A 组，才说"装了以后更容易交出东西"。相等或更少就不说这句。
- **R3 时间准不准**：在交出了的运行里比准确率的中位数。B 不低于 A 减 10 个百分点算"不比 A 差"；B 高于 A 加 10 个百分点算"更准"；介于两者之间说"相近"。任一组交出的次数是 0，就不比。
- **R4 更快、更省**：只有同时满足才讲：B 交出的次数不少于 A；B 的用时中位数小于 A 的；B 的额度中位数小于 A 的。中位数只在交出了的运行里算，超时没有额度，所以 A 全部超时就无法比额度，照实写"没法比"。有一项不满足就不讲"更快更省"，并照报哪一项。
- **R5 总是照报**：不管结论如何，每次运行的交没交、用时、额度、准确率、编造条数、B 组读了几个镜头，原样列出；对我们不利的（例如 B 更慢更贵、B 用 shell 绕过关卡）一样列出。
- **作废和重跑**：见第 4 节；不因为"结果不好看"重跑。

**这些数字（±1.0 秒、±10 个百分点、6–12 条、3 对 3）都是我的建议，请审阅时改。**

## 7. 风险和没把握的地方

1. **A 组可能很快交出东西**：V-01 超时是因为任务是逐镜表；这次的任务不要求覆盖全片，A 组可能抽几十张图就够了，那结论就是"这个任务上 A 也行"，照报。
2. **B 组要读 46 个镜头才能写文件**：时间和额度要等测出来；一次会话里 46 张图会不会触到别的限制，没测过（试验里最多测过 6 张）。
3. **B 组可能用 shell 写文件绕过关卡**（验证结果第 8 项）：只记录，不算违规。
4. **每镜头一张中点帧读不全镜头里随时间出现的字**（验证结果第 10 项）：这会让 B 组在 `text-on-screen` 的描述上有缺口，但这个任务只要求时间准，不要求抄字。
5. **次数少**：3 对 3 看不出差异显著与否，只能描述。
6. **模型随版本变**：结果只对这一次、这一个模型版本成立。
7. **EP01 里有真实公司名字**：运行日志和判分结果留在仓库外；进参赛视频或演示页的画面要先挑过。
8. **额度读数**：超时的运行读不到。
