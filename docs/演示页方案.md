# 演示页方案（用户 2026-11-16 拍板）

EN summary: A single static page that lets a judge see, in about two minutes, what RefCov does, replayed from real session logs rather than described. Sections: a one-number hero (without RefCov 13 of 16 runs opened none of the project's guides; with it 16 of 16 read every required unit); a side-by-side replay of one real front-end pair (same prompt, same cheap model); the five-task table with its limits; a replay of the gate on the GIS app (write blocked, 24 cells light up, write allowed); the two apps' unit grids (46-shot strip, 24-cell field table); "we used it on ourselves" (the Haiku build ledger and the same-task Opus vs Haiku cost); what we did not show; and how to try it. Data comes from a stdlib script that trims the raw run logs into small JSON files with paths and answer values removed. Kiro builds it with Haiku under RefCov, with Chrome's guides registered for the page's own folder, so the page is itself an example. Recommended hosting is GitHub Pages. The user approved all five recommendations on 2026-11-16, and the replayed runs are fixed by rule (the first run of each batch) in section 7.

## 1. 目标

评委（Kiro 团队）打开一个网址，两分钟内看懂三件事，而且看到的是**真实记录的回放**，不是文字描述：

1. AI 说按规范写了，其实大多一份没看。
2. 装上 RefCov，它先读完，读了多少是一个数字；没读完就写会被拦下。
3. 我们自己就是这么用的：第二个应用由最便宜的模型在 RefCov 管着写完。

不追求：页面上做实验、联网调用模型、后端。

## 3. 回放的数据从哪来

- 原始记录在仓库外（`D:\agent\kiro\refcov-trial\runs\`），很大，含本机路径。
- 写一个只用标准库的转换脚本（放在演示页文件夹里），把选中的几次运行转成小 JSON：
  - 事件：时间（秒）、类型（工具调用 / 读单元 / 被拦 / 写文件 / 最后的汇报）、单元编号、简短标签。
  - 去掉本机路径（换成相对路径）、去掉模型的思考过程、截短长文本。
  - **不放标准答案的数值**：GIS 的回放只显示"写出 answer.md，在标准值 ±3% 内"，不显示面积数字。
- 生成的 JSON 进仓库，演示页只读这些 JSON。
- 版权和隐私：
  - 参考视频的画面里有真实公司名，**不放关键帧**，只放格子；
  - Chrome 指南是 Apache-2.0，可以显示单元标题；
  - 纽约数据只显示字段名。

## 4. 怎么做

- **技术**：一个静态页面，纯 HTML、CSS、JS，不用框架、不用构建工具，数据是同目录下的 JSON。
- **谁做**：Kiro 用 Haiku，按规格流程走（需求 → 设计 → 任务），每步停在检查点给 Claude 审。施工账接着记，第三幕又多一份实证。
- **建议：演示页本身也在 RefCov 管着写**。给演示页的文件夹配上必看材料：Chrome 指南里和这页相关的几份，用指南包自带的检索按规则选，和前端扩展试验同一个办法。这样页面本身就是一个例子："这页是最便宜的模型先读完指南再写的"。配置由用户改、用户运行 `refcov sync`。
- **托管：建议用 GitHub Pages**。仓库本来就是公开的，自带 HTTPS，不用维护服务器，在线到 2027-01-29 没问题；部署从三天缩到几小时。东京服务器留作备用。
- **时间**（接冲刺计划第 4 节）：
  - 11-16：拍板本方案；
  - 11-17：需求；
  - 11-18：设计；
  - 11-19 – 22：做；
  - 11-23：审；
  - 11-24 – 25：上线。

## 5. 要用户拍板的

1. **托管**：GitHub Pages（建议）还是东京服务器？
2. **主角回放用哪一对**：
   - 第一轮账户设置页的 Haiku 一对（建议）：主证据，四处写法 0 对 3–4，最好懂；
   - 前端扩展里 FAQ 的一对：同时有一次被拦，但任务不是主证据。
3. **演示页是否也在 RefCov 管着写**（建议是）：要你在 `refcov.toml` 里加一段配置，再运行一次 `refcov sync`。
4. **语言**：只做英文（建议，评委看英文），还是中英两版？
5. **镜头条不放关键帧图片**（建议照此）：参考视频里有真实公司名。

## 6. 不做的

- 不在页面上跑模型、不连后端、不收集访客数据。
- 不做"实时演示"：都是回放，并写明是哪一次运行、哪天、什么模型。
- 不为了好看挑数字：回放的那几次在方案定下后就固定，结果表照实列全部运行。
