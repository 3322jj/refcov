# 前端扩展试验设计：再加 4 个任务

EN summary: The main evidence so far (docs/前端指南试验结果.md) comes from one front-end task. This trial asks whether the same pattern holds on four more common front-end tasks: an FAQ accordion, a dropdown navigation menu, a dark-mode switcher, and a long article page with scroll effects. Same corpus (Chrome's modern web guidance, 210 guides, v1.0.0), same model (claude-haiku-5.5), same harness (fresh headless kiro-cli process per run, prompts that mention neither the guides nor RefCov). One change answers the "you picked the material" objection: the registered guides are no longer chosen by Claude but by the corpus's own `search` command (one query per requirement, top 3 results, union). Each task has 3–5 "needles": a guide-recommended practice for a requirement that an old habit also satisfies. A probe of 1 run per group per task comes first; the pre-written rule decides whether all four tasks are filled to 3 runs per group. Nothing is run before the user approves this design.

Claude 写，2026-11-15 夜，**等用户批准后才跑**。用户可以改任务、改针、改判定规则；跑之前改，跑之后不改。

## 1. 为什么做

主要证据（`docs/前端指南试验结果.md`）只有一个任务（账户设置页），对外只能说"在这个任务上测得"。这次只回答一个问题：

> 换成另外 4 个常见的前端任务，Haiku 不装 RefCov 时会不会也不看指南、照老习惯写；装上后会不会读完并用上指南的写法？

不回答：页面在浏览器里好不好用（只查有没有脚本错误）；其他模型（自动选模型和 Sonnet 太贵，这次不跑）。

## 2. 和上一轮相同的

- 材料：Chrome 官方现代前端指南（`modern-web-guidance` 包 v1.0.0 的 `guides/`，210 份，Apache-2.0）。工作区就是上一轮的 `W-template`，README 一句话原样不改："Front-end code in this project follows the guides in guides/ (Chrome's modern web guidance)."
- 模型：claude-haiku-5.5；kiro-cli 开跑前记版本（上一轮是 3.3.0）。
- 运行：每次从模板复制一份新工作区，临时目录设在副本里，起一个新的无界面 kiro-cli 进程；不用子代理，不让 AI 自己答题。
- 提示词：英文，只描述页面要做什么，不提指南，不提 RefCov。
- 判分方式：查生成的代码里有没有指南推荐的写法；查记录里有没有打开指南。

## 3. 和上一轮不同的：登记哪些指南由规则定，不由 Claude 挑

上一轮登记的 8 份指南是 Claude 按任务挑的，四根针所在的指南都在里面，这一点在结果文档里照实交代过。这一轮改成规则：

- 每条要求写一个英文短语，用指南包自带的检索命令 `modern-web.mjs search` 检索，**取前 3 个结果，去重，全部登记**，严格模式。
- 不手工增删。检索会带进一些不太对口的大指南（例如 `html`、`accessibility`、`forms` 总览），这是规则的代价，照登。
- 检索短语是照着要求写的。设计时已经跑过一次检索（结果见各任务的表），所以 Claude 是看过结果才定稿的，这一点照实写在这里。

登记用简化上手的路径：模板的 `refcov.toml` 写 `[sources] files = [...]`，由用户在终端运行 `setup.py` 和 `refcov sync`。

## 4. 四个任务

每个任务有几根"针"：某条要求，指南推荐一种新写法，老习惯也能做到。判分只看新写法用没用上。

### T1 FAQ 手风琴

提示词：

```
Build index.html (plain HTML, CSS and JS, no framework): an FAQ section with six questions and answers. Only one answer may be open at a time. Opening and closing an answer should animate smoothly. The browser's find-in-page (Ctrl+F) must be able to find text inside collapsed answers.
```

| 针 | 要求 | 指南推荐（出处） | 判分（正则，不分大小写） | 老习惯 |
|---|---|---|---|---|
| T1-1 | 一次只开一个 | `<details name="...">` 互斥（`accordion`） | `<details[^>]*\sname=` | JS 打开一个时关掉其他 |
| T1-2 | 平滑展开收起 | `interpolate-size: allow-keywords` 加 `::details-content` 过渡（`accordion`、`animate-to-intrinsic-sizes`） | `interpolate-size\s*:\s*allow-keywords` 或 `::details-content` 或 `calc-size\(` | `max-height` 技巧、JS 量 `scrollHeight` |
| T1-3 | 页内搜索能搜到折起来的答案 | 用 `<details>`（内容用 `content-visibility` 隐藏，能被搜到），或 `hidden="until-found"`（`accordion`、`search-hidden-content`） | `<details` 或 `until-found` | JS 加 `display: none` |

登记（检索短语 → 前 3）："accordion"、"exclusive accordion one open"、"animate expand collapse height"、"find in page hidden content" → `accordion`、`html`、`search-hidden-content`、`animate-to-intrinsic-sizes`、`interactive-content-reveal`、`accessibility`。6 份，117 个单元。

### T2 下拉导航菜单

提示词：

```
Build index.html (plain HTML, CSS and JS, no framework): a top navigation bar with a "Products" button that opens a dropdown menu of five links, positioned right below the button. Clicking outside the menu or pressing Escape closes it. Put a second, identical button at the far right edge of the bar; its menu must stay fully inside the viewport. The menu should fade in when it opens.
```

| 针 | 要求 | 指南推荐（出处） | 判分 | 老习惯 |
|---|---|---|---|---|
| T2-1 | 点外面、按 Esc 关闭 | `popover` 属性，浏览器自带轻关闭（`menu`、`light-dismiss-a-dialog`） | `\spopover(\s*=\|[\s>])` | `document` 上监听点击和按键 |
| T2-2 | 按钮打开菜单 | `commandfor` + `command="toggle-popover"`，或 `popovertarget`（`menu`） | `commandfor=` 或 `popovertarget=` | JS 切换显示 |
| T2-3 | 菜单贴着按钮 | CSS 锚点定位，不用 JS 坐标（`menu`、`viewport-aware-dropdowns`） | `anchor-name` 或 `position-anchor` 或 `position-area` 或 `anchor\(` | `getBoundingClientRect`，或父元素相对定位 |
| T2-4 | 靠右的菜单不出视口 | `position-try-fallbacks`（`viewport-aware-dropdowns`） | `position-try` | JS 量宽度后翻转 |
| T2-5 | 打开时淡入 | `@starting-style`（`animate-element-entry-exit`） | `@starting-style` | JS 下一帧再加类 |

登记："dropdown menu"、"close popup on outside click"、"keep dropdown inside viewport"、"animate popup entry" → `menu`、`viewport-aware-dropdowns`、`select-menu-interaction`、`light-dismiss-a-dialog`、`navigation-drawer`、`navbar`、`animate-element-entry-exit`、`scroll-entry-exit-effects`。8 份，92 个单元。

### T3 深色模式切换

提示词：

```
Build index.html (plain HTML, CSS and JS, no framework): a settings page with a theme switcher offering System, Light and Dark. System follows the operating system setting. The choice is remembered across reloads. The page contains a text input, a select and a checkbox; these native controls and the page scrollbar must match the active theme.
```

| 针 | 要求 | 指南推荐（出处） | 判分 | 老习惯 |
|---|---|---|---|---|
| T3-1 | 原生控件和滚动条跟着主题变 | CSS 的 `color-scheme`（`dark-mode-toggle`、`dark-mode`） | `color-scheme` | 手工给每个控件写颜色 |
| T3-2 | 颜色按主题切换 | `light-dark()`，颜色只写一处（`dark-mode-toggle`、`component-specific-light-dark-theme`） | `light-dark\(` | 在 `.dark` 类和媒体查询里各写一套变量 |
| T3-3 | 三档切换 | 改 `<meta name="color-scheme">`（`light dark` / `light` / `dark`）（`dark-mode-toggle`） | `<meta[^>]+name=["']color-scheme` | 给 `html` 加类或 `data-theme` |

登记："dark mode toggle"、"follow system color scheme"、"theme native form controls" → `dark-mode-toggle`、`dark-mode`、`component-specific-light-dark-theme`、`color`、`brand-consistent-forms`、`browser-ui-theming`、`forms`。7 份，101 个单元。

### T4 长文阅读页

提示词：

```
Build index.html (plain HTML, CSS and JS, no framework): a long article page with at least eight sections of placeholder text. A thin bar at the top shows reading progress as the user scrolls. The site header shrinks smoothly over the first 150 pixels of scrolling. Each section heading sticks to the top while its section is on screen, and shows a shadow only while it is stuck.
```

| 针 | 要求 | 指南推荐（出处） | 判分 | 老习惯 |
|---|---|---|---|---|
| T4-1 | 阅读进度条 | 滚动驱动动画 `animation-timeline: scroll()`（`scroll-progress-indicator`） | 进度条的动画由 `animation-timeline` 驱动 | 监听 `scroll` 事件改宽度 |
| T4-2 | 页眉随滚动缩小 | `animation-timeline: scroll()` 加 `animation-range: 0 150px`（`shrinking-header-on-scroll`） | 页眉的动画由 `animation-timeline` 驱动 | 监听 `scroll` 事件切类 |
| T4-3 | 吸顶时才有阴影 | `@container scroll-state(stuck: top)`（`state-aware-sticky-headers`） | `scroll-state\(\s*stuck` | `IntersectionObserver` 哨兵元素 |

T4-1 和 T4-2 用同一个属性，正则分不出是哪个元素，所以先用正则找出 `animation-timeline`，再由 Claude 看它在哪个选择器上。这两根针按"该元素的动画由 `animation-timeline` 驱动"判，同时有 JS 降级不扣分。

登记："reading progress bar"、"shrink header on scroll"、"sticky header style when stuck" → `progress`、`progress-ring`、`scroll-progress-indicator`、`shrinking-header-on-scroll`、`content-first-noise-reduction`、`state-aware-sticky-headers`、`responsive-table`。7 份，54 个单元。

合计 14 根针。

## 7. 跑之前写下的判定规则

- **单个任务"测出差别"**：H0 多数次没打开登记的指南，且 H1 平均比 H0 多用上至少一半的针（例如 4 根针，平均多用上 2 根以上）。
- **探路之后**：4 个任务里至少 2 个在探路中出现"H0 没打开登记的指南、H1 用上的针更多"，就 4 个任务全部补到每组 3 次；不到 2 个就停下，照实写结果，不补跑、不换任务、不改针。
- **全部结果都写进结果文档**，包括测不出差别的任务。
- **读后取舍**：有些写法只在部分浏览器可用（例如 `interpolate-size`、`scroll-state`、锚点定位）。H1 读了指南后选了保守写法的（上一轮 `commandfor` 就是这样），照样按没用上计分，但在结果里单列说明。
- **对外说法按结果定**，连同原来的任务一起说，例如"5 个前端任务里有 X 个……"。

## 10. 预想的问题

- **有的针老习惯里就有**：例如 FAQ 很多人本来就用 `<details>`，这根针两组可能都用上，差别变小。照实写，不换针。
- **有的写法太新**：模型可能根本不知道（例如 `scroll-state`、`@starting-style`）。这属于"模型不知道的新东西"那一层，读了指南才可能用上；判分照常。
- **检索规则带进大指南**：T1 的 `html`、`accessibility` 有 80 个单元，读的成本更高。这是规则的代价。
- **次数少**：每组最多 3 次，仍是描述，不做统计结论。
