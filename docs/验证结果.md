**做法**

- 探测服务：`experiments/mcp-image-cli/image_server.py`，照 IDE 验证用的那份重写（零依赖 stdio），颜色名改成英文，工具 `get_test_image` 加了 `count` 参数（1 或 2，返回几张图）。每张图是 3x3 的色块 PNG，颜色每次随机。正确答案只写进仓库外的 `D:\agent\kiro\image-probe-cli\answer.jsonl`，工具返回的文字里没有。
- 运行文件夹：`D:\agent\kiro\image-probe-cli\run-1\`（仓库外，里面只有 `.kiro/settings/mcp.json`，指向上面的服务）。
- 命令：`kiro-cli chat --v3 --no-interactive --trust-all-tools --model claude-haiku-5.5 --output-format stream-json --require-mcp-startup <提示词>`，提示词在 `image-probe-cli\prompt.txt`：只许用这个工具，调用两次（先 `count` 1，再 `count` 2），逐行说每格颜色，看不到就直说、不要猜。
- 这是一次基础设施探测，不是答题试验，所以没有经 `run_trial.py`（用户 2026-11-14 在任务里指定了这条命令）。

**结果**

| 图 | 模型的回答 | 服务端答案 | 对的格数 |
|---|---|---|---|
| 第 1 次调用，第 1 张 | 黑 红 白 / 白 蓝 绿 / 白 白 红 | 同左 | 9/9 |
| 第 2 次调用，第 1 张 | 绿 绿 红 / 黑 绿 蓝 / 蓝 蓝 白 | 同左 | 9/9 |
| 第 2 次调用，第 2 张 | 红 白 红 / 绿 黄 白 / 黑 黄 蓝 | 同左 | 9/9 |

（颜色在原始日志里是英文：black、red、white 等。）

- 27 格全对。答案不在文字里，所以模型只能靠看图答对。一次工具结果里带 2 张图也能都送到。
- 用时 45 秒，额度 0.045（事件流里的 `session_usage`），工具调用：`load_resource` 一次、`tool_call` 两次（模型先加载了 MCP 工具的说明，再调用）。
- 事件流里，两次调用的 `completed` 更新都带图片内容块。
- `answer.jsonl` 里有两条 `start`：MCP 服务进程启动了两次。**推测**是 CLI 先试新版协议握手、不认识再重起，和第 6 项在 IDE 里看到的一样；没有单独验证。

**局限**

- 只测了 1 次、1 个模型、3x3 色块的小图（300x300 像素，事件流里一张图连同包装约 3.5 KB）。没有测真实关键帧（视频帧是 JPEG/PNG，几十到几百 KB）会不会被截断或缩小，也没有测一次返回很多张的情况。
- 模型能"看到"不等于能读出画面里的小字；镜头应用要靠关键帧读画面文字，这一点要等适配器做出来后用真实关键帧再测。

**对设计的意义：** CLI 里 MCP 工具可以把图片送到模型，镜头应用让 `read_unit` 返回关键帧图片在 CLI 里走得通。真实关键帧的大小和张数上限是镜头应用需求里要定的参数。
