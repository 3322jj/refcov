### 和第一轮对不上的地方（要如实记下）

第一轮（15:15–15:21）用 `fs_write|str_replace|fs_append`、`write`、"不设匹配条件"三种写法，6 次写入**一次都没触发**，日志里连记录都没有。第二轮除了新加的三个精确名钩子，**第一轮那三个老钩子也全都触发了**，日志如下：

### 其他实测（第一轮，仍然有效）

## 第 2 项：钩子能拿到的信息 —— 成立

钩子从 stdin 收到一段 JSON。

| 信息 | 字段 | 实测 |
| --- | --- | --- |
| 事件名 | `hook_event_name` | 有 |
| 会话 ID | `session_id`（环境变量 `KIRO_SESSION_ID` 里也有） | 有 |
| 工作目录 | `cwd` | 有，为工作区根目录 |
| 工具名 | `tool_name` | 有：`fs_write`、`str_replace`、`fs_append`、`read_file`、`execute_pwsh`、`createHook` |
| `fs_write` 参数 | `tool_input` = `{path, text}` | 有，和 AWS Labs 记录一致 |
| `str_replace` 参数 | `{path, oldStr, newStr, replace_all}` | 有 |
| `fs_append` 参数 | `{path, text}` | 有 |
| `read_file` 参数（被读文件路径） | `{path, offset, limit}` | 有 |
| shell 命令全文 | `{command, description, cwd, run_in_background, timeout}` | 有 |
| 工具返回结果（PostToolUse） | `tool_response` | 有（`execute_pwsh`） |
| 写完后的文件路径 | PostFileCreate / PostFileSave 的 `file_path` | 有 |

需要注意：

- 子 agent 的工具调用也会触发工作区的钩子。
- 钩子看到的是**整段输入**，包括要写进去的正文。正式关卡只能按 `path` 判断，不能在全文里搜关键词，否则会误拦（这次就拦到了我自己的检查命令）。
- 用 shell 读文件时，只拿得到命令全文，被读文件的路径要自己解析，可能漏记。

## 对三层关卡的结论

1. **MCP 工具（主关卡）：** 图片能送到，开工凭证由 MCP 服务发。不依赖钩子。
2. **钩子关卡：** `fs_write` / `str_replace` / `fs_append` / shell 都能用退出码 2 加 stderr 拦住，按 `tool_input.path` 判断。PreTaskExec 也能用退出码 2 拦住任务开工（第 5 项），任务引用的单元要从 `spec_name` 指向的 tasks.md 里自己解析。
3. **事后记录：** 用 PostFileSave 加 `file_path` 记一笔，在报告里标红，不自动恢复文件。
4. **覆盖率提示：** 用 UserPromptSubmit 的 stdout，已实测能送到我这里（每次你发消息送一次）。
